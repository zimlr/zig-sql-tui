# Security policy

## Supported versions

Security reports are accepted for the latest published release and the current development source. Maintainers assess affected versions and backports for each report. Older versions may require an upgrade.

## Private reporting

Report suspected vulnerabilities through [GitHub private vulnerability reporting](https://github.com/zimlr/zsqt/security/advisories/new). A GitHub account is required. No alternative private reporting channel is currently listed. Do not submit undisclosed vulnerabilities through public issues, pull requests, or commit messages.

Include the affected version, operating system, impact, reproduction steps, and a minimal test case when available. Remove credentials, personal data, and database contents that are not required to reproduce the issue. State any disclosure constraints in the private report.

Maintainers review reports privately, assess their impact, and coordinate remediation and disclosure with the reporter. Response and remediation times depend on the report and maintainer availability. No fixed response deadline is guaranteed.
